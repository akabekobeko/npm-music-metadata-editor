## サマリー

致命的な脆弱性は **検出されず** (Critical / High / Medium 0 件)。本差分は (1) ID3v2 `TCON` の `(17)` / `17` / `(RX)` / `(CR)` 記法をジャンル名へ解決する `resolveGenreText` の新設、(2) MP4 `gnre` アトム用に重複定義されていたジャンル表の `tags/id3v1` 共有表 (148 件) への統合、(3) MP3 書き込み時に ID3v1 ジャンル バイトが常に `0xFF` になるバグの修正、(4) `ID3V1_GENRES` の公開エクスポート。信頼できないファイル バイト列を起点とする攻撃経路を重点的に検証した。

|  | 件数 (差分起因) | 件数 (継続) |
| --- | --- | --- |
| Critical | 0 | 0 |
| High | 0 | 0 |
| Medium | 0 | 0 |
| Low / Informational | 0 (INFO 1 件は下記所見参照) | v1.0.0 の LOW-1〜LOW-6 / v1.0.2〜v1.0.4 の INFO (据え置き) |

検証した攻撃経路と結論:

1. **プロトタイプ汚染 / 継承プロパティ参照** — `SPECIAL_GENRES` は攻撃者由来トークンでインデックスする Plain Object だが、トークンは正規表現キャプチャ `\d+|RX|CR` に制約され `__proto__` / `constructor` 等は到達不能。参照は read-only で代入経路も存在しない。
2. **配列境界** — 数字のみのトークンへの `Number.parseInt` は負値や `NaN` になり得ず、過大値は `code < ID3V1_GENRES.length` で棄却。`resolveGnreIndex` は `readUInt16BE` (長さガードつき) の `[0, 65535]` 値を 1-based → 0-based 変換後に範囲チェックしており、境界外アクセスは到達不能。80 件表 → 148 件表への拡大は解決可能な名前の集合を広げるのみ。
3. **ID3v1 書き込みバイト** — `resolveGenreByte` は「検証済み `[0, 255]` 整数」「148 件表の `findIndex` 結果 (< 256)」「`0xFF`」のいずれかのみを返し、1 バイト外の値は書き込みに到達しない。`genreCode` の optional 化はガード追加を伴い検証を強化する方向の変更。
4. **文字列処理の終了性・injection sink の不在** — `resolveGenreText` のループは 1 参照ごとに最低 3 文字消費するか break するため必ず終了する。refinement テキストは生のまま返すが、これは従来 (フレーム テキスト全体を無加工で代入) と同等でありシンクも存在しない。
5. **新規攻撃面の不在** — 新しいファイル I/O・パス操作・動的評価・データ露出は追加されていない。

## 良い点 (Strengths)

- **トークンの構文制約** — 参照トークンを正規表現で `\d+|RX|CR` に限定してから look-up する構成により、object-injection 系の問題を構造的に排除している。
- **ジャンル表の単一情報源化** — MP4 側の重複表 (80 件・不完全) を削除し `tags/id3v1` の 148 件表へ統合したことで、表の不整合に起因する将来の齟齬 (同じコードが形式によって別名に解決される等) を防いでいる。
- **境界テストの拡充** — `(255)` / `255` / index 0 / index 149 など範囲外入力の挙動 (無加工で保持 / `undefined`) を単体テストで固定している。

## 所見 (Findings)

**差分起因の脆弱性は該当なし**。継続項目 (v1.0.0 の LOW-1〜LOW-6、v1.0.2〜v1.0.4 の INFO) は本差分で変更されたコードに該当せず据え置き (悪化なし)。

- **INFO-1: 公開した `ID3V1_GENRES` が実行時には可変配列** — 型上は `readonly string[]` だが `Object.freeze` されていないため、ライブラリ利用側コードが実行時に要素を書き換えるとプロセス全体のジャンル解決が歪む。悪意あるオーディオ ファイルからは到達不能で、利用側の自傷に限られるため脆弱性ではない (hardening 候補)。必要なら `Object.freeze` で閉じられる。
