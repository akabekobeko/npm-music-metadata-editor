## サマリー

致命的な脆弱性は **検出されず** (Critical / High / Medium いずれも 0 件)。差分は `TagData.producer` の追加と、各タグ形式 (ID3v2 involved people list / Vorbis Comment / APE / MP4 freeform / WMA) へのマッピング実装。

## 良い点 (Strengths)

- **新規バイナリ パーサーの境界安全性** — `parseInvolvedPeopleFrame` は `Uint8Array.subarray` によるビュー分割のみで構成され、フレーム本体の範囲外を読む経路が無い。encoding byte は 4 エントリー固定マップで `undefined` ガード済み。空 / 不正 body は空配列を返し例外を投げない。
- **フレーム境界の隔離** — ID3v2 のフレーム境界はヘッダーの length フィールド由来のため、TIPL/IPLS 内に不正なセパレーターが混入しても影響は当該フレーム内に閉じ、他フレームへのデシンクは発生しない。
- **GUI に XSS 経路なし** — `tag.producer` は React JSX のテキスト補間 (`TextCell`) で描画され自動エスケープされる。`dangerouslySetInnerHTML` 等の unsafe API は renderer に存在しない。
- **書き込み経路は既存ファンネルを再利用** — Vorbis / APE / WMA / MP4 は既存の長さ計算付きエンコーダー (`stringifyValue` / `utf8Value` 等) を通るため、文字列内容によるコンテナー構造の偽装は不可。

## 所見 (Findings)

### `feat/support-producer-field` 差分起因

#### INFO-1: `tag.producer` 内の NUL 文字による involved-people role 注入 (修正済み)

- **場所**: `packages/core/src/tags/id3v2/writeId3v2/mergeProducerFrame.ts`
- **内容**: involved people list は NUL を構造セパレーターとする文字列リストのため、呼び出し側が `"X\u0000engineer\u0000Mallory"` のような値を渡すと、次回パース時に意図しない role/name ペアとして解釈される。
- **判定**: false-positive フィルタの結論は「呼び出し側は自分が書き込むファイルの全フレームを既に自由に制御できるため信頼境界を越えない。セキュリティ脆弱性ではなく堅牢性 (データ整合性) の問題」(確信度 2〜3/10 で閾値 8 未満)。
- **対応**: 同ブランチで `mergeProducerFrame` に NUL 除去 (`replaceAll("\u0000", "")`) を追加し、role 注入を防止するテストを追加済み。
- **残課題 (informational)**: ID3v2.3 (`IPLS`) 書き込みは Latin-1 エンコードのため、Latin-1 で表現できない文字 (例: U+0100) は `Buffer.from(value, "latin1")` の低バイト マスクにより `0x00` 等へ化ける。これは producer に限らず v2.3 の全テキスト フレーム共通の既存挙動であり、本 PR での悪化は無い。将来 v2.3 書き込みを UTF-16 対応させる際に併せて解消するのが妥当。

継続項目 (v1.0.0 の LOW-1〜LOW-6、v1.0.2〜v1.0.3 の INFO 各 2 件) は本差分で変更されたコードに該当せず据え置き (悪化なし)。
