## サマリー

致命的な脆弱性は **検出されず** (信頼度 0.7 以上の所見ゼロ)。本バージョンの差分は MP4 atom ツリー パーサーのトップレベル限定の末尾ゴミ許容と、書き込み時の末尾バイト保持のみ。

差分の中身:

- `parseRange`: トップレベルかつ `moov` パース済みかつ type 4 バイトが fourcc としてあり得ない場合のみ、不正ヘッダーでパースを打ち切り残りを無視 (従来は常に例外)。コンテナ内部と「type は妥当だが size が不正」なケースは従来どおり例外を維持
- `isPlausibleAtomType` (新規): fourcc 妥当性判定 (印字可能 ASCII 0x20–0x7E と `©` 0xA9 のみ許可)
- `reassembleFile`: 最終トップレベル atom 以降のバイトを出力へそのまま引き継ぐ (ATL.NET の in-place 書き換えと同等の挙動)

|  | 件数 |
| --- | --- |
| Critical | 0 |
| High | 0 |
| Medium | 0 |
| Low / Informational | 2 (下記 INFO-1 / INFO-2) |

境界チェックの検証: リファクタリング (即時 throw → `failure` 文字列の集約判定) 後も全ての境界ガードが維持されている。`readUInt64` は `pos + LARGE_BOX_HEADER_SIZE <= end` の場合のみ呼ばれ、`size < headerSize` / `pos + size > end` の検査順序も不変。ゴミ打ち切り時 (`break`) は atom を push せず `pos` も進めないため、範囲外読み取りは発生しない。`reassembleFile` の `tailStart = lastAtom.offset + lastAtom.size` はパース停止位置と厳密に一致し、`0 <= tailStart <= source.length` が保証される。付加されるバイトは常に同一入力ファイル由来であり、他ファイルのデータ混入はない。

## 良い点 (Strengths)

- **許容条件の三重ゲート** — トップレベル限定 + `moov` パース済み + fourcc 不成立、の全成立時のみ許容。truncate された実 atom (type が妥当な fourcc) や本体破損ファイルは従来どおり例外となり、黙って空メタデータを返す退行がない。
- **書き込み往復の自己整合性** — 保持された末尾バイトはファイル長と同じデルタで移動するため、再パース時も同じ境界で決定的に打ち切られる。stco/co64 は moov 内 (末尾より前) にあり、チャンク オフセット再計算との不整合は生じない。
- **ランタイム依存ゼロを維持** — `dependencies` は引き続き空。攻撃面の増加はパーサー ロジックのみに限定される。

## 所見 (Findings)

### INFO-1 — ポリグロット ファイルの受理 (parser differential)

- **内容**: 末尾ゴミ許容により、`moov` 以降に非 fourcc バイト列が続くファイル (例: ZIP を後置した MP4 ポリグロット。`PK\x03\x04` は 0x03 を含むため「ゴミ」と判定される) が、従来の拒否から受理に変わる。
- **評価**: 攻撃者はファイル全体を制御できる立場にあり、本ライブラリ内で信頼境界は越えない。ffmpeg 系や ATL.NET など主要実装も末尾ジャンクを許容しており、本ライブラリが突出して寛容になるわけではない。悪用には「不正ヘッダーを越えてスキャンする特定の下流コンシューマー」が必要で投機的。confidence 0.5 で報告閾値未満。
- **対応**: 現状維持。セキュリティ検証用途 (アップロード検査など) に本ライブラリを使う場合は、末尾バイトの存在を別途検査する必要がある点に留意。

### INFO-2 — 末尾バイトの残置 (residual data)

- **内容**: 保持される末尾バイトには、他ツールの in-place 書き換えが残した旧タグ内容などが含まれ得る。タグを書き換えてもこの領域はスクラブされない。
- **評価**: 修正前は該当ファイルを拒否していた (スクラブしていたわけではない)。バイトはユーザー自身の入力ファイル由来で、ファイル間のデータ露出はない。ATL.NET 互換の意図的挙動としてコード内に文書化済み。
- **対応**: 現状維持。将来「末尾ゴミの明示的な削除オプション」を追加する場合は API として提供する。

v1.0.0 の LOW-1〜LOW-6 について、本差分での悪化はなし (ファイル I/O・公開 API・タグ検証経路に変更なし)。

## 次回更新時のチェックリスト

core のバージョンを上げる PR では新しい `v1.x.y.md` を作成し、以下を再評価:

- [ ] v1.0.0 の LOW-1〜LOW-6 (シンボリック リンク follow ほか) が当該 PR で悪化していないか
- [ ] 末尾ゴミ許容の条件 (トップレベル / `moov` 済み / fourcc 不成立) を緩める変更が入る場合は INFO-1 のポリグロット受理を再評価
- [ ] 末尾バイトを加工・削除する機能を追加する場合は INFO-2 の残置データ方針を API 仕様として明文化
- [ ] `dependencies` にランタイム依存を追加した場合は、当該パッケージの既知 CVE を `npm audit` / GitHub Advisory で確認
