## サマリー

致命的な脆弱性は **検出されず**。本 PR は **実装コードへの変更なし** (core の差分は `package.json` の devDependencies 4 件の range 更新のみ) で、パース / 書き込み経路は v1.1.1 リリース時点から不変。ランタイム `dependencies` は引き続き存在しない。

pnpm 12 で再生成された lockfile と、mise のツール解決経路をサプライチェーン観点で検査した結果は以下のとおり (詳細は「良い点」参照):

- lockfile に追加された resolution 95 件はすべて `integrity: sha512-...` を持ち、`tarball:` / `git+` / `http://` 指定は 0 件。主要 12 パッケージの integrity を npm registry の `dist.integrity` と照合し全件一致。
- インストール スクリプトを持つパッケージは `electron` / `electron-winstaller` / `esbuild` の 3 件のみで、いずれも `pnpm-workspace.yaml` の `allowBuilds` に登録済み (後者 2 件はバージョン不変)。
- `pnpm audit`: 既知脆弱性なし。

## 良い点 (Strengths)

- **実装コード非変更** — core の差分は `@tsconfig/node24` / `@types/node` / `tsx` / `vitest` の devDependencies range 更新のみ。公開物 (`dist/`) に影響する依存は無い。
- **lockfile の来歴が健全** — 追加 95 エントリー全件が sha512 integrity 付きで公開 npm registry (`registry.npmjs.org`) を参照。`tarball:` / `git+` / `github.com` / `http://` の grep は 0 件。`overrides` / `patchedDependencies` / pnpmfile の新設なし。追加・削除はいずれも既存パッケージの 1:1 バージョン更新で、新規の推移依存は `powershell-utils@0.2.1` (`open@11` 経由、既知メンテナーの公開リポジトリ) のみ。
- **インストール スクリプト ポリシーが維持** — `hasBin` の新規追加は `pnpm@12.2.1` (bin のみ、lifecycle script なし)。lifecycle script を持つ 3 パッケージは全て `allowBuilds` 登録済みで、`pnpm install --frozen-lockfile` は "Lockfile passes supply-chain policies" を報告し、ignored-build 警告なし。
- **pnpm 12 の既定でサプライチェーン耐性が向上** — `minimumReleaseAge: 1440` (公開後 24 時間未満のバージョンを解決しない) が既定で有効。
- **mise の pnpm 取得経路が署名検証付きに** — aqua backend は GitHub Releases の成果物を cosign / SLSA / minisign で検証してから展開するため、`npm:` backend 経由の取得より来歴保証が強い。
- **検証済** — `pnpm install --frozen-lockfile` / `pnpm typecheck` / `pnpm check` / `pnpm build` / `pnpm test` (core 485 件) が全通過。
