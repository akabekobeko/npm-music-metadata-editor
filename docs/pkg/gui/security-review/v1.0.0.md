## サマリー

致命的な脆弱性は **検出されず**。本バージョンの実コード差分は、GUI のフォーマット対応マトリクスに `supportsPictureKind` (画像種別を保持できる形式か) フラグを追加し、保持できない形式 (MP4 `covr` 等) では画像ダイアログの種別セレクタを無効化する UX 改善が中心。あわせて種別 Select の表示ラベルを `t(`pictures.kind.${value}`)` で i18n 化している。

差分の中身:

- `packages/gui/src/main/ipc/formatSupport/buildFormatSupportMatrix.ts`: `FormatCapability` に `pictureKind: boolean` を追加し、ハードコードされた capability テーブルへ各形式の値を設定。MP4 `covr` のみ `false`
- `packages/gui/src/main/ipc/types.ts`: IPC 境界の `FormatSupportEntry` に `supportsPictureKind: boolean` を追加
- `packages/gui/src/renderer/components/app/AppShell/useDialogState.ts`: `pictureKindEditable` を導出。`activeRow` 不明時や support エントリ未解決時は `true` 既定 (明示 `false` のみブロックする open-gate ポリシーに準拠)
- `packages/gui/src/renderer/components/app/AppShell/ActiveDialogs.tsx` / `PicturesDialog.tsx` / `PictureForm.tsx`: `kindEditable` を伝搬し、`false` のとき種別 Select を `disabled` 化 + 説明文を表示。Select 表示ラベルを `t(`pictures.kind.${value}`)` 化
- `packages/gui/src/shared/locales/en.ts` / `ja.ts`: `pictures.kindUnsupported` メッセージを追加
- `*.test.ts(x)` 4 ファイル: `supportsPictureKind` フィールドをテスト フィクスチャ/スナップショットに追加 (テスト専用)

## 良い点 (Strengths)

v0.0.0 → v1.0.0 で確立した防御線をすべて踏襲。本ブランチの変更は構造的にも以下の点で安全:

1. **動的 i18n キーの値が固定 enum 由来** — `PictureForm.tsx` の `t(`pictures.kind.${value}`)` に渡る `value` は `PICTURE_KIND_VALUES` (定数配列 0–20) と `<Select value={String(draft.kind)}>` に由来し、攻撃者制御の文字列がキーに到達しない。
2. **`lookup()` がプレーンなプロパティ参照** — `packages/gui/src/shared/locales/t.ts` の辞書参照は単純な property read で、ミス時はキー文字列をそのまま返すフォールバックのみ。`eval` / `Function` / ファイル アクセスは無く、`__proto__` 等のキーでも値を *書き込まない* ため prototype pollution は発生しない。戻り値は表示テキストとして扱われるのみ。
3. **XSS 経路なし** — 翻訳結果は通常の React テキスト子として描画。`dangerouslySetInnerHTML` 等の危険 API は差分に存在しない。
4. **IPC 境界を通る新フィールドは静的 boolean** — `supportsPictureKind` はハードコード テーブル由来のシリアライズ可能な真偽値で、新規の動的経路・コマンド実行を追加しない。
5. **`pictureKindEditable` は UX ガードであり信頼境界ではない** — クライアント側 Select の無効化のみで、実際の永続化は core ライブラリが保存時に担当。保存できない編集を防ぐ UX 改善であって認可境界ではない。
6. **`webPreferences` / IPC チャネル / ナビゲーション制御は非変更** — `sandbox: true` / `contextIsolation: true` / `nodeIntegration: false` を維持し、新規 IPC ハンドラー・`will-navigate` / `setWindowOpenHandler` の追加もない。

## 所見 (Findings)

### `feat/gui-improve-picture-dialog` 差分起因の新規 Finding

**該当なし**。本ブランチの実コード変更は capability フラグの追加と Renderer の表示制御のみで、injection / XSS / 認証 / 暗号 / 動的コード実行 / ファイル I/O のいずれにも新規経路を追加していない。

検証済の保留 (false positive 判定):

- **動的 i18n キー `t(`pictures.kind.${value}`)` によるキー インジェクション / prototype pollution 懸念**: `value` は固定 enum (`PICTURE_KIND_VALUES`) 由来で攻撃者制御不可。`lookup()` は読み取り専用のプロパティ参照で書き込みを行わないため pollution 不成立。sub-task 判定 confidence 9/10。

### v0.1.0 から継続している LOW (`feat/gui-improve-picture-dialog` で悪化なし)

- **LOW-2 — Content-Security-Policy が未設定 (継続)**: `packages/gui/src/renderer/index.html`。本ブランチでも未対処。React 経由で文字列はエスケープされるため XSS 経路は依然として無いが、二段目の防御として CSP の適用が望ましい。
- **LOW-3 — クリップボード ペーストにセーフ ガードが無い (継続)**: `useKeyboard.ts` の `dispatchPaste`。本ブランチではキーボード / ペースト ハンドラ非変更。
- **LOW-4 — `onSaveTrack` の許可リスト未実装 (継続)**: `packages/gui/src/main/ipc/onSaveTrack.ts`。本ブランチで Main / IPC ハンドラに変更なし。
