## サマリー

致命的な脆弱性は **検出されず**。本バージョンの実コード差分は **`packages/gui/src/main/main.ts` への Chromium スイッチ 2 行の追加のみ**。残りは依存パッケージ・パッケージ バージョンの更新で、Electron のセキュリティ設定 (`contextIsolation` / `nodeIntegration` / `sandbox`) や IPC・ナビゲーション制御には一切触れていない。

差分の中身:

- `packages/gui/src/main/main.ts`: 起動時に `app.commandLine.appendSwitch("use-mock-keychain")` (macOS) と `app.commandLine.appendSwitch("password-store", "basic")` (Linux) を追加。Chromium の Cookie 暗号化が OS 資格情報ストアへアクセスして起動時にパーミッション ダイアログを出す問題を回避する目的
- `package.json`: `version` を 0.5.0 → 1.0.0
- `package.json` (devDependencies): `electron` 42.3.0 → 42.3.3 / `electron-builder` 26.8.1 → 26.15.0 / `react` `react-dom` 19.2.6 → 19.2.7 / `shadcn` 4.8.3 → 4.10.0 / `vite` 8.0.14 → 8.0.16 / `vitest` 4.1.7 → 4.1.8 / `@tanstack/react-virtual` 3.13.26 → 3.14.2 / `@types/node` `@types/react` ほか
- `pnpm-lock.yaml`: 上記に追従

## 良い点 (Strengths)

v0.0.0 → v0.5.0 で確立した防御線をすべて踏襲。本ブランチの変更は構造的にも以下の点で安全:

1. **`webPreferences.sandbox: true` / `contextIsolation: true` / `nodeIntegration: false` の維持** — `packages/gui/src/main/main.ts`。本 PR で `webPreferences` は一切変更されておらず、Renderer サンドボックスの境界線は維持。
2. **`safeStorage` 不使用の確認** — grep により本アプリは `safeStorage` / `encryptString` を一切使用していないことを確認 (唯一の一致は main.ts のコメント自身)。アプリ設定は `app.getPath("userData")` 配下のプレーン ファイルとして保存され、追加した 2 スイッチとは独立している。
3. **キーチェーン スイッチが新規攻撃面を増やさない** — `use-mock-keychain` / `password-store=basic` が影響するのは Chromium 自身の Cookie / HTTP キャッシュ暗号化キー (os_crypt) のみ。オフラインのメタデータ編集アプリであり、`file://` / dev サーバー由来の origin から機微な資格情報を Cookie に保持しない。新規の IPC ハンドラー・`will-navigate` / `setWindowOpenHandler` の追加もない。
4. **`expandDroppedPaths` の三重防御 (継続)** — `lstat` (symlink を辿らない) / 深さ 3 制限 / 拡張子 allowlist は変更なし。
5. **IPC チャネル / `MenuAction` union (継続)** — 新規 IPC channel / action の追加なし。

## 所見 (Findings)

### `feat/update-deps` 差分起因の新規 Finding

**該当なし**。本ブランチの実コード変更は main プロセスの起動時スイッチ 2 行のみで、IPC チャネル / ファイル I/O / 動的コード実行 / shell 起動 / 認証 / 暗号 API のいずれにも新規経路を追加していない。

検証済の保留 (false positive 判定):

- **`use-mock-keychain` / `password-store=basic` が秘密情報を平文化する懸念**: 本アプリは `safeStorage` を使用しておらず、これらのスイッチが影響するのは Chromium 自身の Cookie / キャッシュ暗号化のみ。暗号化されていた秘密情報がそもそも存在せず、「暗号化ストアからプレーンテキストへ秘密情報が移動する」事象は発生しない。なお機微情報のディスク保存は HARD EXCLUSION (secrets stored on disk) にも該当。
- **Electron / Vite / React のメジャー〜パッチ更新に伴う既知 CVE 懸念**: 依存更新は別途管理対象 (outdated-library) であり本レビューのスコープ外。electron は 42.3.0 → 42.3.3 のパッチ更新で `webPreferences` 既定値の変更なし。

### v0.1.0 から継続している LOW (`feat/update-deps` で悪化なし)

- **LOW-2 — Content-Security-Policy が未設定 (継続)**: `packages/gui/src/renderer/index.html`。本ブランチでも未対処。React 経由で文字列はエスケープされるため XSS 経路は依然として無いが、二段目の防御として CSP の適用が望ましい。
- **LOW-3 — クリップボード ペーストにセーフ ガードが無い (継続)**: `useKeyboard.ts` の `dispatchPaste`。本ブランチではキーボード / ペースト ハンドラ非変更。
- **LOW-4 — `onSaveTrack` の許可リスト未実装 (継続)**: `packages/gui/src/main/ipc/onSaveTrack.ts`。本ブランチで Main / IPC ハンドラに変更なし。
