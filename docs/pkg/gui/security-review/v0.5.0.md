## 良い点 (Strengths)

v0.0.0 → v0.1.0 → v0.5.0 (前回 `feat/gui-improve-cell-styles`) で確立した防御線をすべて踏襲。本ブランチの DnD 追加は構造的にも以下の点でプラス:

1. **`webPreferences.sandbox: true` の維持 (継続)** — `packages/gui/src/main/main.ts`。Renderer サンドボックスの境界線は維持。
2. **`expandDroppedPaths` の三重防御 (継続)** — `lstat` (symlink を辿らない) / 深さ 3 制限 / 拡張子 allowlist は変更なし。
3. **`webUtils.getPathForFile` 経由の D&D path 解決 (継続)** — preload は byte 単位で同一なので Renderer が `File` を偽造して絶対パスを得る経路は引き続き無い。
4. **IPC `MenuAction` の閉じた string union (継続)** — `packages/gui/src/main/ipc/types.ts`。新規 IPC チャネル / action の追加なし。
5. **`shell.openExternal` の URL がハードコード (継続)** — Renderer 由来の URL 流入経路は無い。
6. **ログ転送が出力先プロセス内のみ (継続)** — `onLogForward` / `onFatalReport` は外部 echo back しない。
7. **`mergeSettings` の明示フィールド戦略 (継続)** — `theme` / `locale` は scalar のみ採用。
8. **`resolveLocale` の allowlist (継続)** — `SUPPORTED_LOCALES` (`["en", "ja"]`) との一致比較で safe fallback。
9. **ランタイム依存ゼロ ポリシー (継続)** — 本ブランチでも追加なし。HTML5 native DnD で実装したため `@dnd-kit` 等の新規依存を増やしていない。
10. **`@mme/ipc` 仮想モジュールが型のみ (継続)** — `import type` 限定で TypeScript が elide。
11. **`pnpm-workspace.yaml` の `allowBuilds` map (継続)** — postinstall 実行は明示許可した 4 パッケージのみ。
12. **`useEditableCell` / `EditableCell` の commit pipeline は不変 (継続)** — 本ブランチでセル編集経路は触っていない。
13. **`reorderColumnIds` が pure function として単独テスト可能 (本ブランチ新規)** — `packages/gui/src/renderer/features/spreadsheet/reorderColumnIds.ts`。順序入替ロジックを副作用なしの関数に切り出し、`reorderColumnIds.test.ts` の 6 件で全分岐 (after / before / source==target / unknown target / no-op / 先頭移動) を網羅。ロジック差分が他コンポーネントに浸食しない構造。
14. **`useColumnDragAndDrop` が DOM 操作と React state のみで完結 (本ブランチ新規)** — `packages/gui/src/renderer/components/app/Spreadsheet/SpreadsheetHeader/useColumnDragAndDrop.ts`。`dataTransfer.setData("text/plain", columnId)` は Firefox の non-empty payload 要件を満たすためだけに使い、**`onDrop` 側では `dataTransfer.getData` を読まず、React state `draggingId` を source of truth とする**。これにより、cross-window / cross-origin の偽 drag (`text/plain` を細工して別オリジンから drop) が reorder を発火させる経路を構造的に塞いでいる。
15. **`useColumnSettings.reorderColumns` で `fileName` 先頭固定を強制 (本ブランチ新規)** — `packages/gui/src/renderer/components/app/AppShell/useColumnSettings.ts`。Renderer 内のいずれの呼び出し経路 (DnD / 仮に malformed な orderedIds が流れ込んでも) でも `["fileName", ...withoutFileName]` で正規化したうえで `setSettings` に渡す。`buildColumns` 側の `fileName` 自動 prepend と二重防御。
16. **`mergeColumns` が `visibleIds` を array として wholesale 置換 (継続)** — `packages/gui/src/main/settings/mergeSettings.ts:68`。Renderer が patch する `visibleIds` は `patch.visibleIds ?? current.visibleIds` で **配列ごと差し替え** されるため、prototype pollution (`__proto__` / `constructor.prototype` キーを忍ばせる) のような attack vector は構造的に成立しない。array merge / deep merge を経由しない設計を本 PR でも維持。
17. **`useDragAndDrop` の `isFileDrag` ガード追加 (本ブランチ新規)** — `packages/gui/src/renderer/features/dnd/useDragAndDrop.ts`。`event.dataTransfer.types.includes("Files")` で OS ファイル drag だけを window listener が拾うように **狭めた**。これは信頼境界を緩めるのではなく、内部 DnD (列並び替え) が window listener に吸収されて `dropEffect = "copy"` で上書きされる副作用を排除するための **narrow 化**。事前は「外部ファイル drag のみ取り扱う想定だがフィルタが緩く `text/plain` 等も走っていた」状態だったので、結果的に attack surface が縮小する。`onPaths` に到達する条件は `types.includes("Files")` が真のときのみ、すなわち OS の File オブジェクトを伴う drag に限定され、これまで通り `webUtils.getPathForFile` の絶対パス解決を経由する。
18. **HTML DnD の payload が consumer 側で読まれない設計 (本ブランチ新規)** — 任意の外部ページ (Electron renderer の `webview` / iframe が将来導入されるケース) が偽の `text/plain` で drag を仕掛けても、reorder 経路は React state ベースの `draggingId` を見ているため、外部発の drag に対しては `draggingId === null` のままで早期 return する。

## 所見 (Findings)

### `feat/gui-change-column-order` 差分起因の新規 Finding

**該当なし**。本ブランチは Renderer 内の React TSX / Tailwind class / TypeScript 型定義に閉じており、IPC チャネル / ファイル I/O / 動的コード実行 / shell 起動 / 認証 / 暗号 / ナビゲーション制御のいずれにも触れていない。新規 IPC channel / action の追加もなく、`setSettings` 経由の patch は既存の `mergeColumns` の wholesale 置換規約を守っている。

検証済の保留 (false positive 判定):

- **`dataTransfer.setData("text/plain", columnId)` 経由の untrusted data 流入懸念**: `onDrop` ハンドラは `dataTransfer.getData(...)` を **読み出していない**。`useColumnDragAndDrop` の React state `draggingId` のみを参照して reorder を決めるため、cross-origin / 偽 drag の `text/plain` ペイロードを使った reorder 誘導は構造的に不可。
- **`visibleIds` が `setSettings` で main に渡る prototype pollution 懸念**: `mergeColumns` は `patch.visibleIds ?? current.visibleIds` で **配列を丸ごと差し替える**。deep merge / `Object.assign` の連鎖を通らないため `__proto__` / `constructor.prototype` を介した汚染は成立しない。
- **`buildColumns` が `COLUMN_REGISTRY[id]` で未知 id を引いた場合の挙動懸念**: 未知 id は `undefined` 解決となり render が壊れるが、これは安定性 (DoS 系) であってセキュリティ脆弱性ではない (HARD EXCLUSION 1)。なお、Renderer 内で `setSettings` を発行する経路は `useColumnSettings` と既存の `useFileOpen` / `useMenuActions` のみで、いずれも `ALL_COLUMN_IDS` または既存 settings のいずれかを起点にしており、外部入力から未知 id が流入する経路は無い。
- **`<div draggable>` ラッパー追加に伴う UI redress 懸念**: 追加した `<div>` は `<th>` 内部に閉じた leaf 要素で、新しい iframe / overlay / dialog は導入していない。stacking context の z-index も既存値 (`z-40` / `z-50`) を踏襲。clickjacking 等の文脈で攻撃に転用できる新規 overlay は無い。
- **`useDragAndDrop` の `isFileDrag` ガード追加が外部ファイル drop 経路を緩めるか**: ガード追加前は「`text/plain` などの内部 drag も window listener が拾って `dropEffect = "copy"` していた」状態。追加後は OS の File オブジェクト (`types.includes("Files")` が真) のときのみ反応するように **絞った** ため、`onPaths` が呼ばれる条件は厳密化されており、信頼境界は緩まらない (むしろ縮小)。

### v0.1.0 から継続している LOW (`feat/gui-change-column-order` で悪化なし)

- **LOW-2 — Content-Security-Policy が未設定 (継続)**: `packages/gui/src/renderer/index.html`。本ブランチでも未対処。React 経由で文字列はエスケープされるため XSS 経路は依然として無いが、二段目の防御として `default-src 'self'` ベースの CSP を `<meta>` か `onHeadersReceived` で適用するのが望ましい。Vite dev サーバーが `'unsafe-eval'` を要求するため production のみ適用する分岐が必要。
- **LOW-3 — クリップボード ペーストにセーフ ガードが無い (継続)**: `packages/gui/src/renderer/components/app/Spreadsheet/useKeyboard.ts` の `dispatchPaste`。Phase 8 で改行を含む列 (`Lyrics`) と payload が opaque な列 (`Pictures`) の列方向 broadcast 経路は型レベルで塞がれているが、「短文系列を列選択して 1 値ペースト → 全行 fill」のケース (Phase 4 broadcast 規則の本来動作) で、`applyPaste` 前段に「行数 > rows.length」「セル長 > N KiB」の確認ダイアログを挟む価値が引き続き残る。本ブランチではキーボード / ペースト ハンドラ非変更。
- **LOW-4 — `onSaveTrack` の許可リスト未実装 (継続)**: `packages/gui/src/main/ipc/onSaveTrack.ts`。本ブランチでは Main / IPC ハンドラに変更が無いため、`filePath` 経路の数 (dialog / recentFiles / D&D / Open Recent) は v0.1.0 と同じ。

**結果: 致命的な脆弱性は検出されず。**

- `scripts/*.ts` の subprocess sink (`spawn` / `spawnSync` / `execFileSync`) は変換前から存在し、いずれもハードコード リテラル・パッケージ相対パス・信頼される CLI 引数のみで駆動。`get-electron-target-env.ts` の `-e` eval 文字列に補間される `key` は `"chrome"` / `"node"` のリテラル限定。新たな未信頼入力経路の追加なし。
- `readFileSync` / `writeFileSync` の対象はすべてパッケージ ルート基準のハードコード相対パスで、パストラバーサル経路なし。
- electron 41 → 42 のメジャー更新: 上記チェックリストの「Electron のメジャー アップデート時」項目に沿って Release Notes を確認。`webPreferences` / `contextIsolation` / `sandbox` の既定値変更なし。v42 では npm postinstall でのバイナリ ダウンロードが廃止され初回実行時取得に変更されており、`@electron/get` 経由の postinstall 攻撃面はむしろ縮小。本 PR で main / preload / IPC のコードは未変更。
- `vite.config.ts` の target 文字列変更はセキュリティ非該当。
