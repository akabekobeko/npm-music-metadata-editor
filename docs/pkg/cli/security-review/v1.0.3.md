## サマリー

致命的な脆弱性は **検出されず**。CLI 側の差分は 2 ファイルのみ:

- `src/commands/write/types.ts`: `STRING_TAG_FIELDS` に `"producer"` を追加 (既存の型付きフィールド テーブル経由で `--producer <s>` フラグが機械的に生成される)
- `src/commands/read/formatTrack/formatPretty.ts`: pretty 出力に `Producer` 行を追加

## 良い点 (Strengths)

- **新規シンクなし** — `--producer` の値は commander → 型付き override テーブル → core の既存 `stringifyValue` / writer ファンネルを通り、シェル補間やテンプレート評価は存在しない。CLI フラグは信頼済み入力 (攻撃者がフラグを制御できる環境ではより直接的な攻撃が可能) であり、新しい攻撃面を導入しない。
- **出力は既存パターン** — pretty 出力はタグ値を既存のフィールド ループでプレーン テキスト出力するのみで、producer 固有の処理は無い。

## 所見 (Findings)

### `feat/support-producer-field` 差分起因の新規 Finding

**該当なし**。core 側で検出された INFO-1 (NUL による role 注入、修正済み) は CLI 入力経路にも波及しうるが、core の `mergeProducerFrame` で NUL 除去が実装されたため CLI 側の追加対応は不要。

## 次回更新時のチェックリスト

- [ ] `STRING_TAG_FIELDS` へ新規フィールドを追加する際、core 側でそのフィールドに構造的なメタ文字 (セパレーター等) が無いか確認する
- [ ] 既存レビューの継続項目を再評価する
